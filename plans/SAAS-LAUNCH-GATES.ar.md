# سجل شروط إطلاق منصة المطاعم والتحقق الخارجي

تاريخ المراجعة: 30 سبتمبر 2026. يكمل هذا السجل [مواصفات وخطة التحول](SAAS-TRANSFORMATION-PLAN.ar.md) بعد اعتماد حفظ جميع الوظائف والتراخيص وواتساب QR/Cloud API وإدارة الويب، وإضافة ChatGPT وFlutter. دليل النموذج المحلي الأول مسجل منفصلًا؛ أصبح نشر بيئة الاختبار المحمية على أصل النطاق ودخول المختبرين مثبتين، دون اعتماد ChatGPT أو Events أو الإنتاج. الجمهور هو مالك المشروع وفريق التنفيذ، ونجاح النموذج لا يغلق شروط التشغيل.

القرار المعتمد: الإقامة السعودية تشمل قواعدنا وملفاتنا وصورنا وسجلاتنا ونسخنا الاحتياطية المخزنة؛ معالجة ChatGPT وموقعه ونسخ مزودي الخدمات ليست ضمن ضمان استضافتنا. لذلك لا ينتظر الإطلاق اتفاق OpenAI سعوديًا خاصًا. أذن المالك بالنموذج المعزول ذي المطعمين وفق [عقد النموذج](../prototype/CONTRACT.md)؛ قبول الإنتاج ما زال يحتاج إثبات التخزين والنسخ والحسابات والدفع والنشر العام، وتوسيع قبول الهوية والعزل من نطاق الاختبار إلى النطاق الإنتاجي.

نُشرت وجهة الاختبار فعليًا على الخادم الموجود وأصل `https://almujeeb.info` دون نطاق فرعي، مع Caddy نشط ودون fallback إلى النظام القديم، ودخول Dex لأربعة مختبرين مسموحين. حساب المالك ChatGPT Pro معلوم، لكن قبوله الفعلي لم يثبت بعد. نقل الاستضافة مؤجل. لا بيانات أو أموال حقيقية في النموذج، ولم ينفذ backup أو snapshot في هذه المرحلة بطلب المالك. تبقى النسخ والاستعادة شروط إنتاج ونقل لاحقين، لا شرطًا لإنشاء لقطة أثناء تجربة النطاق الحالية.

## 2 OpenAI وحدود الإقامة وإتاحة المنتج

توضح [ضوابط الإضافات](https://learn.chatgpt.com/docs/enterprise/apps-and-connectors) أن قواعد الخدمة المتصلة لا تستبدل قواعد ChatGPT، وتربط [وثيقة أمن Work](https://learn.chatgpt.com/docs/enterprise/chatgpt-work-cloud-security) الإقامة بالمنتج والميزة والمنطقة والعقد. وثائق [إقامة بيانات API](https://developers.openai.com/api/docs/guides/your-data) تخص API؛ لا تستخدم كضمان لحسابات جمهور ChatGPT. لا نعد بإقامة سعودية لنسخ OpenAI، ولا نطلب اتفاقًا سعوديًا خاصًا لأن المالك حصر الشرط في تخزيننا نحن.

القرار التقني: نجمع بيانات التسليم الدقيقة في موقعنا الآمن ونخزنها داخل السعودية، ونرسل لبوابة الدفع ما تحتاجه لتنفيذ العملية فقط. لا تعاد استجابات البوابات الخام أو دفاتر الطلبات عبر MCP، وتقتصر الأحداث على مرجع طلب وحالة ونسخة ووقت. رموز الطلب ومعلومات الحساب المستعارة قد تظل قابلة للربط بشخص، والعميل قد يكتب بياناته بنفسه في ChatGPT؛ لذلك يفصح عن المعالجة الخارجية وحقوق الوصول والاحتفاظ لدى المزود دون وعد بحذف نسخ لا نتحكم بها. لا تعد عناوين iframe أو إخفاء حقل عن النموذج دليلًا على عدم وصوله إلى المضيف.

ما يحتاج إثباتًا فعليًا في حساب ChatGPT Pro الذي حدده المالك: إتاحة Extension على الواجهات المستهدفة، توافق SDK والبروتوكول، OAuth واكتشاف الصلاحيات، العرض والـcheckout الخارجي، واشتراك Events وتوقيعه وإلغاؤه. نطاق HTTPS المعتمد هو `https://almujeeb.info` نفسه؛ تضبط OAuth وموارد UI وHost/Origin وسياسات المصادر عليه، ثم تحقق الناشر والنطاق ومراجعة النشر للإتاحة العامة. لا يقترح نطاق فرعي بدل القرار المعتمد، وإثبات هذه القدرات في الحساب منفصل عن محاكاة البروتوكول محليًا.

أثبتت [وثائق Extensions](https://developers.openai.com/plugins/build/extensions) واجهات الامتداد وحدود الإتاحة حسب السطح والخطة، ووثقت [MCP Events](https://developers.openai.com/plugins/build/mcp-events) الاشتراك والتسليم غير المتزامن. أما [تقديم الإضافة](https://developers.openai.com/plugins/deploy/submission) فمسار تحقق ومراجعة منفصل عن إنشاء نموذج شخصي. لم يثبت بعد قبول حساب المالك أو توافق SDK عبر واجهة ChatGPT المستهدفة فعليًا، ولا نعد بإتاحة مجانية أو إشعار فوري مضمون أو قبول النشر. تبقى مصفوفة الأجهزة والحسابات جزءًا من A06 وA07 في الخطة.

يستمر النموذج ببيانات اصطناعية؛ أُغلق منتقي الهويات ومسار `/dev/session` غير المحمي على النطاق، واستبدلا بدخول Dex لأربعة مختبرين محددين مع ربط خادمي بسجلاتهم الاصطناعية. أثبت اختبار HTTPS دخولهم فعليًا؛ لا يسمى نجاحه قبولًا لتفويض ChatGPT أو Events على حساب OpenAI. تسجل نتائج كل مستوى منفصلة، وتبقى بيانات الحساب وأسراره خارج الوثائق العامة. نشر بيئة الاختبار مثبت في [دليل staging](../prototype/staging/README.ar.md)، ونجح OAuth وMCP عبر النطاق في106 تحققات مع اعتراض عودة ChatGPT محليًا قبل الشبكة في التشغيل النهائي؛ لا يغني ذلك عن تجربة الحساب نفسه.

## 3 الخادم الحالي للاختبار وVPS السعودي للإنتاج اللاحق

اختار المالك الاستضافة الذاتية على VPS سعودي للإنتاج لاحقًا وأجّل نقل الخادم. يستمر التطوير والاختبار على الموجود؛ نُشرت الوجهة المعتمدة `almujeeb.info` ببيئة معزولة دون توجيه إلى خدمات النظام القديم. لا يشترط التصميم حساب Google Cloud أو CNTXT أو خدمات مُدارة، ولا شراء الآن. قبل تخزين بيانات حقيقية يسجل مزود VPS وموقع القرص ونسخه التلقائية ومواصفاته ووجهة النسخ المستقلة، ثم يختبر إعداد النشر؛ وجود عنوان IP سعودي وحده ليس دليل موقع كل تخزين. الجدول التالي مواصفات تشغيل وقبول مستقبلية، وليس أمرًا بتنفيذ نسخة أو لقطة في المرحلة الحالية.

| المكوّن | القرار المطلوب عند التنفيذ | دليل القبول وحدوده |
| --- | --- | --- |
| تطبيق المطعم | خدمة Docker مستقلة لكل مطعم؛ صورة واحدة لكل إصدار وإعدادات ووسائط منفصلة | فحص بصمة الصورة والتوجيه وحدود CPU وRAM والقرص، وعدم تفرع الكود بحسب المطعم |
| PostgreSQL | قاعدة ودور محدود وبيانات مستقلة لكل مطعم، وقاعدة مركزية مستقلة | اختبارات رفض بدور DB نفسه، شبكة داخلية، وعدم نشر منفذ DB للعامة؛ لا دور شامل في تطبيق المطعم |
| SaaS وMCP | بوابة مركزية بهوية وأدوار ورمز خدمة منفصل لكل مطعم | اختبارات العضوية والملكية وعدم قبول عنوان خدمة أو ترويسات موثوقة من العميل؛ لا ربط `docker.sock` بالخدمة العامة |
| الملفات والصور | وحدات تخزين خاصة بكل مطعم داخل السعودية، مع فصل العام والخاص | مطابقة الصور والملفات بعد النقل وفحص منع العبور، دون تغيير لقطات الطلبات القديمة |
| السجلات والمراقبة | تخزين سعودي وتنقيح PII وحدود حجم وتدوير وتنبيه | فحص وجهات السجلات والتصدير وأخطاء النسخ والسعة، دون أسرار أو بطاقة أو نص محادثة خام |
| النسخ والتعافي | نسخ مشفرة في وجهة سعودية مستقلة عن المضيف وحسابه التشغيلي | استعادة قاعدة وملفات ومفاتيح على مضيف سعودي نظيف؛ snapshot في القرص نفسه ليست نسخًا مستقلة |
| الأسرار والتشغيل | مفاتيح خارج DB والصورة وGit، بصلاحيات محدودة ومادة استعادة مستقلة | تدوير وإبطال واستعادة، وتحديث النظام وDocker وPostgreSQL والصور والشهادات بمسؤولية المالك وفريقه |

يبقى واتساب QR وCloud API مع وظائف الجلسات والاتصال والرسائل والترجمة والتسجيل وChatwoot والأرشيف القائمة ضمن حدود مطعمها؛ لا تحذف مكتباته أو واجهاته أو وحداته لتجهيز SaaS. تطبق الاستحقاقات وإذن المالك داخل الخادم والعمال وwebhooks. التعطيل يمنع أعمالًا جديدة عبر القناة ويوقف الإرسال المعلق وفق حالة مسجلة، دون إلغاء طلب قائم أو دفعة أو استرداد أو حذف جلسة. لا يستأنف الطابور القديم تلقائيًا دون مراجعة الصلاحية ومنع التكرار. تبقى إدارة الويب وواجهة المندوب والخمس قوالب فعالة، ويضاف Flutter إليها.

الحاويات تشترك في نواة المضيف وموارده؛ عطل VPS قد يوقف كل المطاعم عليه، واختراق المضيف أو Docker قد يتجاوز عزل الحاويات. لا يوفر فصل الشبكات والقواعد وحده HA أو عزلًا ماديًا. تضبط الخدمات غير الجذرية والصلاحيات الدنيا وحصص الموارد والجدار الناري، وتفصل تهيئة Docker ذات الامتياز عن واجهات الجمهور. تصبح متابعة التحديثات والثغرات والشهادات والمراقبة والنسخ مسؤولية تشغيل مستمرة على المالك وفريقه.

تشمل مراجعة التخزين قواعد المطاعم والمنصة، الصور والملفات، السجلات والمراقبة والتصدير والمؤقتات والنسخ ومواد فك التشفير. تمنع وجهات نسخ أو سجلات تلقائية خارج السعودية. النسخ التي ينشئها مزود ChatGPT أو الدفع في خدمته مستقلة عن ضماننا، وتشرح في الخصوصية؛ لا يمتد شرط المالك إلى مكان الاستدلال أو كل عبور شبكي.

تستعاد بيانات المطعم إلى قاعدة ووحدات تخزين سعودية مستقلة قبل تعديل التوجيه، ثم تعاد سياسات الصلاحيات والنسخ. لا يكتب restore قديم فوق طلبات جديدة أو فوق بقية المطاعم. يحتاج أي هدف PITR إعداد سجل معاملات ونسخ مختبرًا؛ لا ينسب Docker أو توفر القرص وحدهما زمن تعاف أو فقدًا مضمونًا. يختبر مسار مستقل لفقد المضيف قبل إعلان قدرة تحمل ذلك العطل.

أسعار الاشتراك المعتمدة تبقى 149 ريالًا شهريًا أو 1188 سنويًا قبل الضريبة. تقدير 2000–4000 ريال للخدمات المُدارة السابق ليس تقدير هذا VPS؛ يحسب عرض المضيف والقرص والنسخ السعودية المستقلة والنقل والمراقبة ووقت التشغيل، ثم يقارن بالإيراد وقياسات الحمل. هدف 30 ثم 1000 مطعم لا يعني أن خادمًا واحدًا يستوعبهم؛ تحدد عتبات إضافة مضيف سعودي آخر باستهلاك فعلي واختبارات مناسبة، دون تخفيض الأمن لتثبيت سعر غير مقاس.

## 4 اعتماد ميسر وبوابات المطاعم

يوفر [إنشاء الفاتورة](https://docs.moyasar.com/api/invoices/01-create-invoice) صفحة دفع مستضافة وروابط منفصلة للإشعار والعودة، وتعمل [واجهة الاسترداد](https://docs.moyasar.com/api/payments/05-refund-payment) بمعرف الدفعة، لا معرف الفاتورة. توثق [منع التكرار](https://docs.moyasar.com/api/idempotency) إنشاء الدفع؛ لم يثبت من المصادر المفحوصة أن الضمان نفسه يشمل إنشاء فاتورة أو استردادًا. لذلك تحفظ عملية محلية دائمة، ولا يعاد POST مالي مبهم تلقائيًا؛ تتم القراءة والمصالحة ثم المراجعة إن تعذر الحسم.

البند 8 من [سياسة خصوصية ميسر](https://moyasar.com/en/resources/privacy-policy/) ينص على تخزين البيانات الشخصية ومعالجتها داخل السعودية وعدم نقلها خارجها. يبقى ذلك وصفًا لسياسة المزود المنشورة، وتراجع الشروط المنطبقة على حساب المطعم ومسار الربط والإفصاح. نسخ بوابة الدفع خارج ضمان تخزيننا، ولا يشترط قرار المالك إثبات إقامة سعودية شاملة لكل معالجة لدى المزود قبل النموذج؛ تبقى أهلية الحساب وقبول المال والخصوصية واجبة.

تحتاج [أهلية التفعيل](https://moyasar.com/en/resources/faqs/) مستندات نشاط وحسابًا تجاريًا مناسبًا ومراجعة المتجر، وتوجد [شروط خاصة بالمنصات](https://moyasar.com/en/resources/platform-terms-and-conditions/). لا نفترض أن الربط بمفاتيح التجار يعفينا منها أو أنه يفرض علينا تحصيل أموالهم؛ نطلب تحديد مسار SaaS الذي تقبله ميسر، مع ثبات قرار التسوية المباشرة لكل مطعم.

المطلوب لإغلاق G06: حساب اختبار ثم أهلية تشغيل للتاجر، ونطاق ربط المنصة ومعالجة البيانات، وقبول دفع SAR وعزل الحسابات، وفاتورة ذات محاولات متعددة، ودفع مكرر/متأخر، واسترداد جزئي وكامل وغامض أو خارجي متزامن. تقبل حالة الاسترداد فقط بعد إسنادها للدفعة والعملية المقصودة. يبقى الآلي مغلقًا إن تعذر ذلك، مع مسار يدوي لا يدعي تأكيدًا لم يحصل. لا تجرى عملية مالية حقيقية دون تصريح واختيار حساب ومبلغ الاختبار في وقتها.

مسودة سؤال غير مرسلة: «نقدم SaaS يربط كل مطعم بحسابه لديكم وتسوّى أموال الطلبات له مباشرة؛ اشتراك منصتنا منفصل. نرجو تحديد اتفاق الربط المناسب ومسؤوليات التحقق وشروط معالجة البيانات، ووسيلة إسناد الاستردادات ومنع تكرارها عند انقطاع الرد أو وجود استرداد من لوحة التاجر. نحتاج حساب اختبار ولا نطلب تشغيل تحصيل مشترك».

## 5 حقوق دليل المناطق ومصدر بديل مأذون

تطابق النسخة المحلية المصدر المثبت في [README](https://raw.githubusercontent.com/homaily/Saudi-Arabia-Regions-Cities-and-Districts/7e322945fa9f6d696a54ba3e9038e0e750e9692d/README.md) و[LICENSE](https://raw.githubusercontent.com/homaily/Saudi-Arabia-Regions-Cities-and-Districts/7e322945fa9f6d696a54ba3e9038e0e750e9692d/LICENSE). تصريح الناشر أن الجمع من `maps.address.gov.sa` يثبت النسبة التي ذكرها، لا نطاق حقه في إعادة الترخيص. Lite بلا حدود أو مراكز جغرافية؛ لا تستخدم للتحقق من وقوع GPS داخل حي.

يوضح [GNU FAQ](https://www.gnu.org/licenses/gpl-faq.html.en#UnreleasedMods) أن تشغيل GPL المعدل على خادم دون توزيع يختلف عن توزيع البرنامج، بينما [AGPL](https://www.gnu.org/licenses/why-affero-gpl.en.html) يضيف شرط التفاعل الشبكي. قرار حفظ تراخيص النظام معتمد؛ يبقى إثبات حقوق مصدر الجغرافيا ونطاق استخدامها وتوزيعها مستقلًا. خدمة بيانات منفصلة لا تسقط حقوق البيانات المعروضة أو أصلها. لا تغير ملفات المصدر وترخيصها، ولا تدرج الملفات الخام في Flutter أو حزمة موزعة قبل حسم حق التوزيع. هذه مراجعة مصادر، لا رأي قانوني ملزم.

البديل الرسمي المرشح هو [خدمة العنوان الوطني من سبل](https://splonline.com.sa/ar/national-address-api/) وقوائمها في [توثيق API](https://api.address.gov.sa/apidocumentation). القدرة على توفير قوائم المناطق والمدن والأحياء موثقة؛ ليست تكاملًا منفذًا في مشروعنا. صفحات [شروط API](https://api.address.gov.sa/termsofuse) تتضمن قيودًا وصياغة لا تحسم SaaS وإعادة العرض والتخزين؛ والوصف التجاري لا يكفي لاستنتاج ترخيص إنتاج مجاني أو بلا حدود. لا ننتقل إليها أو نحمل بيانات جديدة آليًا في هذه الخطوة.

نغلق G07 بأحد مسارين: تصريح مناسب يغطّي استخدام المصدر الحالي، أو اتفاق مصدر رسمي/مأذون يتيح قوائم الدليل المطلوبة. يجب أن يحدد عرض القوائم عبر الموقع وFlutter وChatGPT، وحق الكاش والنسخ والتحديث والتصدير والنسبة ونهاية الاشتراك، وتكلفة وسعة30 ثم1000 مطعم. تظل كل تصحيحات ورسوم المطاعم مستقلة، ويحتاج أي تبديل للمصدر ربط معرفات صريحًا دون تغيير لقطات الطلبات السابقة.

مسودة طلب غير مرسلة: «نحتاج قوائم المناطق والمدن والأحياء بالعربية والإنجليزية لمنصة مطاعم متعددة المستأجرين. نرجو شروط استخدام تجاري تسمح بحفظ دليل مرجعي سعودي وتحديثه وعرض القوائم اللازمة عبر موقعنا وتطبيق الإدارة وإضافة ChatGPT، مع حدود النسخ والتصدير والنسبة ومدة الكاش، والأسعار والحصص المناسبة لـ30 مطعمًا أول شهر ثم1000 خلال السنة. لا نحتاج إرسال عناوين عملاء لاختبار قوائم الدليل».

## 6 المعلومات الناقصة وحدود العمل المنجز

المعلوم الآن: حساب ChatGPT Pro، ونشر HTTPS فعلي على أصل `almujeeb.info` على الخادم الموجود، ودخول أربعة مختبرين مسموحين عبر Dex، وتأجيل نقل الاستضافة، واعتماد حفظ كل الوظائف والتراخيص، وعدم backup أو snapshot في هذه المرحلة. المتبقي هو قبول الربط والتفويض والواجهة وEvents في الحساب الفعلي، دون إعادة سؤال المالك عن نوع الحساب أو استبدال الأصل بنطاق فرعي. في مواعيدها اللاحقة تحتاج مراحل الإنتاج إلى VPS ونسخ سعودية، وقبول ميسر وحسابات QR/Cloud API المستخدمة وWindows. لا يلزم حساب CNTXT/Google Cloud أو اتفاق OpenAI سعودي خاص، ولا تطلب المفاتيح في المحادثة. الاسم والعلامة مؤجلان وتثبت هوية الناشر عند التحقق.

ما أُنجز: حفظ كل الميزات والقوالب وواجهات الويب وواتساب بنوعيه والتراخيص الحالية، وتوثيق إضافة Flutter وChatGPT ضمن حدود الاختبار والنسخ المعتمدة. يحتفظ [تقرير النموذج](../prototype/README.ar.md) بأدلة النموذج المحلي وحدودها، وتوثق [بيئة staging](../prototype/staging/README.ar.md) النشر المحمي اللاحق. سجل التنفيذ الحالي:

| الدليل | النتيجة المسجلة وحدودها |
| --- | --- |
| المنصة مع PostgreSQL فعلي | 87/87 ناجحًا ودون اختبارات متخطاة |
| الإعدادات السلبية | 3/3 ناجحة منفصلة عن مجموعة المنصة |
| المتصفح مع المحاكاة | 29 تحققًا ناجحًا؛ لا يمثل اتصالًا بحساب ChatGPT |
| متصفح HTTPS الفعلي | 148 تحققًا ناجحًا؛ دخول Dex للأربعة وإكمال طلبين وهميين، عزل عميل/تاجر، CSRF وخصائص cookie، تبديل إعداد القناة وتعارض نسخته وإعادته، والخروج ورفض إعادة الاستخدام |
| OAuth وMCP على النطاق | 106 تحققات ناجحة؛ تفويضان بصلاحيات مختلفة وPKCE وإبطال الرموز وأدوات المطعم. اعترض التشغيل النهائي وجهة العودة محليًا قبل الشبكة مع حظر DNS للوجهات غير نطاق الاختبار؛ لم يُختبر حساب ChatGPT |

| Go والأسرار | 1/1 اختبار السر المركّب ناجح؛ ليس إعلان اجتياز كل اختبارات Go |
| اعتماديات التشغيل | صفر ثغرات معروفة في نطاق فحص الاعتماديات وقت التنفيذ؛ ليست شهادة أمن شاملة |
| استمرار القديم | الحاويات القديمة سليمة وبنفس `StartedAt` والمنفذ المحلي `18787` دون تغيير، والتراخيص الأصلية محفوظة |

النشر فعلي وCaddy نشط ولا يوجد fallback إلى القديم، لكن البيانات والدفع اصطناعيان فقط. لم يُقبل حساب ChatGPT أو Events لديه، ولم تجر اختبارات ميسر الحقيقية أو بناء Windows، ولم تشترَ استضافة جديدة أو تنشأ نسخ احتياطية/snapshots أو تتغير التراخيص. تحكم القناة المختبر إعداد اصطناعي فقط، وليس تشغيلًا حيًا لواتساب QR أو Cloud API. دليل OAuth البروتوكولي أعلاه منفصل عن قبول حساب ChatGPT ومراجعة نشر الإضافة.

لا يتطلب تعديل الوثائق تشغيل اختبارات Go أو Flutter أو متصفح أو قاعدة بيانات. يكتفى بمراجعة الاتساق والأرقام والروابط المحلية والتنسيق؛ تحتفظ اختبارات المال والعزل والاستعادة والحسابات بمكانها عند تنفيذ المراحل المتعلقة بها. لا يدعى اجتيازها بسبب اكتمال هذا السجل.
