# تثبيت نسخة مستقلة من AstraCalls

الملف `astracalls-installer-0.3.0-linux-amd64.run` يحتوي على صور Docker وملفات التشغيل اللازمة لإنشاء نسخة جديدة. لا يحتوي على حسابات واتساب أو طلبات وعناوين عملاء أو مفاتيح OpenAI أو Meta أو إعدادات وبيانات التثبيت الأصلي. تنشأ لكل نسخة قاعدة بيانات وتسجيلات ومفاتيح عشوائية مستقلة، ومنها مفتاح تشفير بيانات اعتماد Meta، ولا يتغير التثبيت الأصلي.

يفتح المطعم العام على `/`، وإدارته المحمية على `/admin`، ولوحة واتساب والترجمة على `/admin/calls`. تبدأ النسخة الجديدة بمنيو تجريبي معلّم وطاولات بروابط مستقلة، دون طلبات أو حسابات عملاء مسبقة. اتبع دليل المطعم المرفق `RESTAURANT.ar.md` قبل استقبال طلبات حقيقية؛ لا توجد بوابة دفع أو شركة توصيل متصلة تلقائيًا.

تنطبق التعليمات على الحزمة النهائية بعد بنائها والتحقق من بصمتها واختبارها. هذا الدليل وحده لا يؤكد اكتمال بناء إصدار أو نشره على خادم قائم، ولا نجاح مكالمة Meta حقيقية.

## المتطلبات

استخدم خادم Linux بمعمارية `x86_64`، عليه Docker Engine يعمل عبر Unix socket محلي، وإضافة Docker Compose تدعم `--wait`، وPython 3 وBash وأدوات النظام المعتادة مثل `tar` و`gzip` و`sha256sum`. شغّل المثبّت بحساب يستطيع استخدام Docker والكتابة في مجلد التثبيت. المثبّت لا يثبت Docker تلقائيًا، ولم يُتحقق من تشغيل هذه الحزمة على معماريات أخرى.

صور التطبيق وPostgreSQL مضمّنة؛ لا يحتاج تثبيتها إلى تنزيل صور من الإنترنت ولا يسحب المثبّت صورًا تلقائيًا. يحتاج تشغيل واتساب وOpenAI لاحقًا إلى اتصال بالإنترنت.

اترك مساحة مؤقتة متاحة تقارب ضعف حجم ملف المثبّت لفك الحزمة، إضافة إلى مساحة صور Docker وقواعد البيانات والتسجيلات. يمكن تحديد مجلد مؤقت أكبر بوضع `TMPDIR=/مسار/مجلد/مؤقت` قبل أمر التثبيت عند الحاجة.

## التثبيت

انقل ملف `.run` إلى الخادم، ثم نفّذ من المجلد الذي تريد إنشاء النسخة داخله:

```bash
bash astracalls-installer-0.3.0-linux-amd64.run --name client1
```

ينشئ هذا الأمر المجلد `./astracalls-client1` ومشروع Docker Compose باسم `astracalls-client1`. يستخدم المثبّت وسوم صور خاصة بالتوزيعة، ويختار تلقائيًا منفذ HTTP متاحًا بدءًا من `8080` ومنفذ وسائط بدءًا من `50000` لكل من TCP وUDP. يأخذ الاختيار في الحسبان المنافذ المستخدمة والمنافذ المحجوزة لحاويات متوقفة، ويعرض عناوين الوصول دون طباعة بيانات الاعتماد.

يمكن تحديد مجلد مطلق ومنافذ ثابتة عند الحاجة:

```bash
bash astracalls-installer-0.3.0-linux-amd64.run \
  --name client1 \
  --dir /srv/astracalls-client1 \
  --http-port 8085 \
  --media-port 50005
```

اختر منافذ متاحة ومجلدًا يملك حساب التشغيل حق الكتابة فيه. لعرض الخيارات:

```bash
bash astracalls-installer-0.3.0-linux-amd64.run --help
```

## الإعداد وربط واتساب

يبقى الوصول افتراضيًا على `127.0.0.1` في الخادم. افتح عنوان الواجهة الذي يعرضه المثبّت من المتصفح على الجهاز نفسه. استخدم الأمر التالي لمعرفة مكان ملف الإعدادات دون عرض محتواه:

```bash
./astracalls-client1/manage.sh config-path
```

افتح الملف الذي يشير إليه الأمر بمحرّر محلي، وأضف مفتاحك في `OPENAI_API_KEY`. احتفظ بملف الإعدادات خاصًا، ولا ترسله أو تنسخ مفاتيحه إلى السجلات أو المحادثات. مفتاح دخول التطبيق هو `WACALLS_API_KEY` الموجود في ذلك الملف؛ استخدمه في شاشة الدخول. بعد تعديل الإعدادات:

```bash
./astracalls-client1/manage.sh restart
```

أمر `restart` يطبّق متغيرات البيئة المعدّلة، ويقطع المكالمات الجارية أثناء إعادة التشغيل. اختر من `/admin/calls` ربط حساب واتساب عبر QR أو WhatsApp Business Platform الرسمي. للخيار الرسمي، اتبع [دليل Meta](META.ar.md) المرفق لإعداد حساب العميل المؤهل وWebhook وبيانات الاعتماد؛ لا يكفي مفتاح OpenAI أو مفتاح تشفير Meta وحده لتفعيل الخدمة الرسمية. إدارة المطعم والطلبات تعمل من `/admin` بالمفتاح نفسه، ولا تتطلب OpenAI أو ربط واتساب.

اختبر المكالمة والترجمة في الاتجاهين بعد الربط. تجهيز الحزمة والاختبارات المحلية لا يعنيان إجراء اختبار مكالمة رسمية أو مترجمة فعلية؛ يتطلب ذلك حساب واتساب مربوطًا أو حساب Meta مؤهلًا ومفعّلًا ومفتاح OpenAI صالحًا.

المتغير `WACALLS_META_ENCRYPTION_KEY` مولّد تلقائيًا لكل تثبيت جديد، ومهم لاستعادة بيانات اعتماد Meta المشفرة. لا تحذفه أو تغيّره عند التحديث، واحفظه مع قاعدة البيانات في نسخة احتياطية آمنة. فقدان المفتاح لا يعطّل QR، لكنه يمنع فتح بيانات اعتماد الحسابات الرسمية المحفوظة. لا يُعاد توليده عند تكرار أمر التثبيت. إذا كنت تحدّث يدويًا نسخة أقدم لا تحتوي عليه، أضف مرة واحدة قيمة Base64 لـ32 بايت عشوائية، مثل الناتج المحلي لأمر `openssl rand -base64 32`، قبل إضافة أول حساب رسمي؛ لا تستبدل قيمة موجودة.

## الوصول من خارج الخادم

للتثبيت مع عنوان خادم عام، استبدل العنوان والنطاق في المثال التالي بقيمك الحقيقية:

```bash
bash astracalls-installer-0.3.0-linux-amd64.run \
  --name client1 \
  --public-ip 203.0.113.10 \
  --public-url https://calls.example.com
```

يقبل `--public-ip` عنوان IPv4 ويجعل ربط الوسائط افتراضيًا على `0.0.0.0`. يبقى HTTP محليًا ما لم تغيّره بواسطة `--http-bind`. ويمكن تحديد عنوان ربط الوسائط صراحةً بواسطة `--media-bind`.

وجّه HTTPS reverse proxy الموجود لديك إلى منفذ HTTP الذي اختاره المثبّت. اسم النطاق في `--public-url` لا ينشئ شهادة أو يضبط الوكيل تلقائيًا. افتح منفذ الوسائط المختار لكل من UDP وTCP، واضبط NAT إن وُجد، ليصل المتصفح إلى العنوان المعلن. يحتاج استخدام ميكروفون المتصفح عن بُعد إلى HTTPS.

## الإدارة وتشغيل نسخة ثانية

استخدم أداة الإدارة داخل مجلد النسخة المقصودة:

```bash
./astracalls-client1/manage.sh status
./astracalls-client1/manage.sh logs
./astracalls-client1/manage.sh stop
./astracalls-client1/manage.sh start
```

الإيقاف والتشغيل يحافظان على قاعدة البيانات والتسجيلات. لإنشاء نسخة مستقلة ثانية في المجلد الحالي:

```bash
bash astracalls-installer-0.3.0-linux-amd64.run --name client2
./astracalls-client2/manage.sh status
```

يختار المثبّت منافذ أخرى عند الحاجة، وتنشأ النسخة في `./astracalls-client2` مع مشروع وبيانات اعتماد ومفتاح تشفير ووحدات تخزين خاصة بها. اربط جلسات واتساب الخاصة بها بصورة مستقلة واضبط Webhook الصحيح للحساب الرسمي. لا تشغّل نسختين على قاعدة بيانات جلسة واتساب نفسها، ولا تستخدم زيادة عدد حاويات التطبيق عبر `--scale`.

## إعادة التثبيت والتحديث

إعادة تشغيل مثبّت الإصدار نفسه على النسخة نفسها تحافظ على إعداداتها وبياناتها ومفتاح تشفيرها وروابط الطاولات، وليست ترقية تلقائية إلى إصدار جديد. مثبّت `0.3.0` يرفض استبدال تثبيت `0.1.0` أو `0.2.0` ضمنيًا. احتفظ بالمثبّت والصور السابقة للرجوع المدروس، واستخدم مسار تحديث صريحًا مع نسخة احتياطية. استخدم اسم النسخة ومجلدها الصحيحين؛ تغيير مجلد العمل مع الاعتماد على المجلد الافتراضي لا يشير إلى مسار التثبيت السابق.

إذا تعذّر بدء التشغيل أو اجتياز فحص الصحة، يحتفظ المثبّت بإعدادات النسخة وبياناتها وأي حاويات أنشأها؛ لا يحذف قواعد البيانات تلقائيًا. افحص الحالة باستخدام `manage.sh status` والسجلات محليًا باستخدام `manage.sh logs`، ثم أعد الأمر نفسه بعد معالجة السبب. لا تشارك السجلات قبل التأكد من خلوها من معلومات حساسة.

قبل أي تحديث، خذ نسخة احتياطية من جميع قواعد PostgreSQL، والتسجيلات، وملف الإعدادات، واحتفظ بالإصدار السابق. توجد خطوات النسخ والتحديث اليدوي في ملف `DOCKER.ar.md` المنفصل ضمن مستودع المصدر؛ عدّل اسم المشروع وملف Compose ومسار الإعدادات لتطابق النسخة المثبّتة. الاستعادة إلى إصدار أقدم تتطلب توافق بنية قاعدة البيانات أو استعادة النسخة الاحتياطية الموافقة لذلك الإصدار. لا تحذف وحدات التخزين أثناء التحديث، لأنها تحمل بيانات الحسابات والتسجيلات.
