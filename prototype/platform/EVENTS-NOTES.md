# Synthetic MCP Events implementation

Reference: [OpenAI MCP Events](https://developers.openai.com/plugins/build/mcp-events), fetched 2026-09-30. Implementing the server side does not establish access to ChatGPT Events or prove a live subscription in a particular account.

- `order.status_changed` is customer-only and requires an owned `tenantId` / `orderId`. The payload includes status, payment status and version; it never includes owner identifiers, addresses or user-authored instructions.
- Subscriptions, verified callback cache and deliveries are in PostgreSQL. The subscription ID is derived from canonical owner, event, filters and normalized callback URL. Secret storage uses AES-256-GCM with subscription ID as authenticated context and an external 32-byte key. Persist that key separately from the database and preserve it for recovery; this prototype does not implement master-key rotation or a secret manager.
- Callback challenges are random, signed, checked with constant-time byte comparison and expire after ten seconds. Successful verification is cached for five minutes per owner, URL and signing key. Rotated signing keys are reverified, then old and new signatures overlap for five minutes.
- Default TTL is 24 hours, capped at seven days. A request for no expiration receives the finite default instead. Subscription refresh is idempotent. Only `cursor: null` is supported: durable queued deliveries survive restarts, but this is not protocol history replay, and events during an expired subscription are not recovered.
- The default HTTPS transport validates DNS on every connection, rejects every DNS answer set containing a non-public address, pins the connection to a validated IP, retains the original TLS hostname, disables redirects and connection reuse, and caps request/response bytes and elapsed time. Port 443 only is an intentional additional restriction. Tests inject a transport; there is no environment setting that permits private or HTTP callbacks in deployment.
- Both platform entry points bind each subscription to its authenticated originating OAuth refresh family, or to its exact code-only session. The binding is server-derived and stores no bearer token. Creation and delivery reauthorize that same connection for the correct owner, resource, events scope and absolute expiry; another active connection for the owner cannot stand in for it. Current order ownership and account eligibility are checked separately. Refresh rotation preserves the family binding; revoked/expired families, removed events scope and revoked/expired code-only sessions fail closed. Pre-upgrade subscriptions without a binding fail closed on dispatch and require an explicitly authorized resubscription.
- Dispatch sends one event per call, using PostgreSQL locks to coordinate workers. Five attempts maximum use exponential delays. HTTP 410 deactivates the subscription; 413 and other non-transient 4xx terminate the delivery. 408, 429, 5xx and network failures retry. Event IDs and serialized payload bytes are stable across retries; signatures use the current attempt time. Delivery is at-least-once: an acknowledgement followed by a database failure can lead to a duplicate. Consumers must deduplicate and tolerate ordering differences.
- Cancellation is serialized with a delivery already in progress; unsubscribe may wait for its bounded HTTPS request to finish. No subsequent delivery starts while a subscription is inactive. Unsubscribe atomically marks existing pending/retry deliveries cancelled; explicitly recreating the subscription does not resurrect those deliveries.
- `revokeAll(principalId)` is a trusted internal platform hook, not an MCP operation. It advances a durable owner revocation epoch, disables all current subscriptions for that owner, marks pending/retry deliveries revoked, and clears only that owner's callback-verification cache in a transaction. It sends no callback and returns no subscription counts or details. The synthetic OAuth revocation route resolves the owner from the token before deleting it and invokes this hook: revoking one valid customer token conservatively stops **all** that customer's current subscriptions, without affecting other owners. The platform remains responsible for token deletion and authentication; this hook does not invalidate other sessions or prohibit a subsequently authorized new subscription.
- Subscription creation snapshots the owner epoch before remote order reads. Callback verification runs without holding database locks, but its cache entry and subscription are persisted together only after transactionally locking and rechecking the original grant and owner epoch. A revocation completed during either remote await prevents the pending operation from recreating its subscription or cache. Grant expiry is an absolute deadline, so callback latency cannot extend it. Revocation and dispatch acquire locks in the same grant → owner → subscription order; a callback already being dispatched can finish before revocation returns, while no later event delivery can use the revoked authority. The additive migration creates `event_owner_epochs`, adds `event_subscriptions.revocation_epoch` and `generation`, and records `event_deliveries.subscription_generation`; existing unbound subscriptions are never assigned an inferred grant. Cancellation, inactive/expired re-creation and originating-grant replacement advance the subscription generation. Existing old-generation retries are cancelled atomically, and dispatch checks generation again so a concurrent enqueue from an older snapshot cannot deliver through a newer connection. Same-live-grant renewal and secret rotation preserve their pending deliveries. Dispatch scans a bounded candidate batch and releases skipped candidates’ locks before trying another, so a busy owner does not block another available delivery.
- A production implementation still needs per-account subscription/delivery quotas, a retention and dead-letter policy, metrics/alerts, encryption-key rotation, and live ChatGPT acceptance. The platform owns polling, scheduling, rate limits and tenant outbox cursors; this module starts no timers.

Run `node --test events.test.mjs event-grants.test.mjs oauth-refresh.test.mjs` for local transport/security tests. Set `TEST_DATABASE_URL` to the disposable prototype platform database to additionally exercise actual PostgreSQL restart persistence, encryption, refresh, ownership, expiry, retries, rotation and concurrency. The integration test creates and removes only its own random schema. Without that variable, it explicitly reports the database suite as skipped.
